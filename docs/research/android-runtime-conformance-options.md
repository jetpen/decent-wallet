# Android runtime conformance proposal for the Kotlin v2 verifier

**Status:** Implemented and runtime-verified on the approved two-AVD matrix. `Medium_Phone` (API 26 Google Play x86) and `Pixel_9` (Android 37.2/API 37 Google APIs Play Store x86_64, 16 KB page size) each pass all nine instrumented cases. The latest evidence is [`docs/reports/issue-36/20260927T025037Z/results.json`](../reports/issue-36/20260927T025037Z/results.json), with per-device XML reports and logs in the same directory. No physical-device or alternate-image fallback is accepted. The Android workflow is Gradle Wrapper-only and uses no Maven command or Maven-produced artifact. Runtime claims are limited to the tested images and cases; no universal Android support is claimed ([issue #36](https://github.com/jetpen/decent-wallet/issues/36)).

## Selected implementation topology

Use a separate, test-only Android **library** module, not an app module, to compile the verifier into an instrumentation test APK and execute it on Android Emulator. Android's library testing model includes the library and its dependencies in the test APK; with no separate app under test, `androidTest` installs only that APK ([Android library testing](https://developer.android.com/studio/projects/android-library)). This meets the “no Android application” boundary while still using Android's ART/runtime.

Do not invoke the existing Maven module for Issue #36 or consume Maven-produced artifacts. Configure the Gradle Android module to compile/reuse the verifier and JSON implementation sources directly and depend on the pinned crypto/parser libraries; do not copy the vector or create a second verifier. Package `tests/vectors/wallet-container-v2.json` into the test APK as an Android test asset from its existing repository path, and read it through the test context. The independent Maven/JUnit 5 verifier module remains unchanged and is outside this Android workflow ([current POM](https://github.com/jetpen/decent-wallet/blob/main/interop/kotlin/pom.xml); [current test](https://github.com/jetpen/decent-wallet/blob/main/interop/kotlin/src/test/kotlin/org/decentwallet/interop/VectorVerifierTest.kt); Android library archives can contain assets per the [AAR reference](https://developer.android.com/studio/projects/android-library#aar-contents)).

Use AndroidX `AndroidJUnitRunner` with JUnit 4 instrumentation tests: Android's documented instrumented-test runner is JUnit 4, while the existing Maven tests use JUnit 5 ([Android instrumented tests](https://developer.android.com/training/testing/instrumented-tests)). Keep the JVM/JUnit 5 suite as-is; add a small Android-facing test wrapper around the same verifier for the vector-positive case and the required wrap/payload tampering, malformed payload, duplicate-name, v1 relabel and unsupported-version paths ([current boundary tests](https://github.com/jetpen/decent-wallet/blob/main/interop/kotlin/src/test/kotlin/org/decentwallet/interop/ContainerV2BoundaryTest.kt), [Issue #36](https://github.com/jetpen/decent-wallet/issues/36)).

## Bounded device matrix and execution

- **API 26 target:** `Medium_Phone`, Google Play x86 system image (32-bit guest). This is the sole API 26 target in the approved matrix. Android's [emulator acceleration requirements](https://developer.android.com/studio/run/emulator-acceleration) permit this selected x86 image on an x86_64 host.
- **API 37 target:** `Pixel_9`, Android 37.2/API 37 Google APIs Play Store x86_64 image with 16 KB page size. This is the exact available current-runtime image; capture its revision and build fingerprint.
- **Coverage boundary:** both named AVDs are required, and the same positive and negative conformance cases run on each. Physical devices and other emulator images do not count. If either selected AVD is unavailable or cannot run, block and seek approval to revise the matrix. The single Gradle instrumentation task is `./gradlew --no-daemon --dependency-verification=strict :interop:android-runtime:connectedDebugAndroidTest`; the repository runner validates and boots both exact AVDs, invokes this task once, and saves device reports. Desktop JVM/Robolectric results are supplemental only.

## Selected Gradle toolchain pins

Use the following Gradle toolchain pins for the Android harness. They were approved in the earlier Issue #36 Gradle proposal and are restored by the current Gradle-only direction; verify them in the first locked build before claiming compatibility.

| Component | Proposed pin | Basis / caveat |
|---|---|---|
| Gradle Wrapper | Gradle 9.5.0 | AGP 9.3 requires Gradle 9.5.0 ([AGP release notes](https://developer.android.com/build/releases/agp-9-3-0-release-notes)). |
| Android Gradle Plugin | 9.3.1 | KGP 2.4.20's published fully-supported AGP range ends at 9.3.1 ([Kotlin Gradle compatibility table](https://kotlinlang.org/docs/gradle-configure-project.html)); use the 9.3 patch release and re-check its R8 bundle before implementation. |
| Kotlin Gradle Plugin/compiler | 2.4.20 | Matches the existing verifier compiler version; KGP 2.4.20 supports Gradle 9.5 and AGP 9.3.1 ([Kotlin compatibility table](https://kotlinlang.org/docs/gradle-configure-project.html)). AGP 9 enables built-in Kotlin by default and rejects simultaneous application of `org.jetbrains.kotlin.android`; to honor the approved explicit KGP 2.4.20 pin, set `android.builtInKotlin=false` and apply KGP 2.4.20. Google's migration guide describes this opt-out as temporary because AGP 10 removes it ([built-in Kotlin migration](https://developer.android.com/build/migrate-to-built-in-kotlin)). |
| Build JDK | 17 | AGP 9.3's required/default JDK is 17 ([AGP release notes](https://developer.android.com/build/releases/agp-9-3-0-release-notes)). |
| Android SDK | `compileSdk 37`, `minSdk 26`, Java/Kotlin bytecode target 8 | AGP 9.3 supports API 37; existing verifier contract targets Java 8 bytecode ([POM](https://github.com/jetpen/decent-wallet/blob/main/interop/kotlin/pom.xml)). Android's build guide distinguishes build JDK from output bytecode/API compatibility ([Android Java versions](https://developer.android.com/build/jdks)). |
| Instrumentation | AndroidX Test Runner 1.7.0 + JUnit 4 | 1.7.0 is listed as a stable runner release ([AndroidX Test release notes](https://developer.android.com/jetpack/androidx/releases/test)); runner/API use is documented in the [instrumented-test guide](https://developer.android.com/training/testing/instrumented-tests). |

Google's Kotlin compatibility table requires AGP 8.5.2+ and R8 9.1.29 for Kotlin 2.4 class files, and states that AGP bundles D8/R8. Kotlin 2.4.20's fully supported AGP range ends at 9.3.1, so AGP 9.3.1 is within the published range and above the required AGP floor; no separate R8 override is proposed. Verify the chosen build pins with a real build before claiming compatibility ([Kotlin/AGP/D8/R8 compatibility](https://developer.android.com/build/kotlin-support), [Kotlin Gradle compatibility](https://kotlinlang.org/docs/gradle-configure-project.html)). Do not substitute AGP 8.13 merely because it requires JDK 17: Google's table associates AGP 8.13's R8 8.13.19 with Kotlin 2.3, not 2.4 ([Kotlin/AGP/D8/R8 compatibility](https://developer.android.com/build/kotlin-support)).

## What the dependency evidence does—and does not—show

- **Bouncy Castle 1.86:** its release-tagged build script describes an AnimalSniffer check against Android API 26 signatures on base/release-8 classes. That is static build-time API-surface evidence, not execution on ART, and does not establish runtime conformance ([BC Android API check at `r1rv86`](https://github.com/bcgit/bc-java/blob/r1rv86/gradle/animalsniffer.gradle)). Issue #33 likewise explicitly limits its accepted API-26 evidence to build-time and disclaims runtime validation ([Issue #33](https://github.com/jetpen/decent-wallet/issues/33)).
- **Jackson Core 2.22.2:** Jackson's README gives a general Android 26+ baseline for 2.14+ and says its Android list is incomplete; that is useful screening evidence, not a published runtime test result for exactly 2.22.2 on API 26 ([Jackson Core README](https://github.com/FasterXML/jackson-core/blob/2.x/README.md)).
- Therefore, the proposed API 26 emulator run is the missing runtime evidence for the exact locked BC/Jackson artifacts and verifier path. Passing it would support only the named Android image/API/ABI and tested cases, not universal Android compatibility.

## Reproducibility controls

Use a checked-in Gradle Wrapper for the exact Gradle version and set `distributionSha256Sum`; Gradle documents this verification for downloaded distributions ([Wrapper verification](https://docs.gradle.org/9.5.0/userguide/gradle_wrapper.html)). Pin AGP, KGP, AndroidX Test, BC, Jackson and all other direct plugin/library versions; check in Gradle dependency lock state for resolved configurations and `gradle/verification-metadata.xml` with SHA-256 entries (and verified signatures where available). Gradle distinguishes version locking from checksums/signatures and supports verification metadata for plugins and transitive artifacts ([dependency locking](https://docs.gradle.org/9.5.0/userguide/dependency_locking.html), [dependency verification](https://docs.gradle.org/9.5.0/userguide/dependency_verification.html)). The existing Maven `lockfile.json` belongs only to the independent JVM module and must not be used by the Android workflow ([Issue #33 lock acceptance](https://github.com/jetpen/decent-wallet/issues/33)).

Gradle dependency locks and verification metadata do not pin Android SDK/emulator images. Record the selected API 26 Google Play x86 and API 37.2 Google APIs Play Store x86_64 image package revisions, ABIs, and build fingerprints with each result; do not count another image or a physical device as a substitute. Android's `sdkmanager` supports installing SDK package paths and listing installed/available packages ([sdkmanager](https://developer.android.com/tools/sdkmanager)).
